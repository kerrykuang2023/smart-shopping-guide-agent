# Product Images

This directory holds all product images referenced from the knowledge base YAML files.

## Naming Convention

```
<sku>-<type>-<index>.<ext>
```

Examples:
- `iphone-15-pro-hero.jpg` (main hero image)
- `iphone-15-pro-front.jpg` (front view)
- `iphone-15-pro-back.jpg` (back view)
- `iphone-15-pro-feature-titanium.jpg` (selling point image)
- `airpods-pro-2-hero.jpg` (related product main image)

## Image Specifications

| Type | Size | Format | Max File Size |
|------|------|--------|---------------|
| Hero (main) | 1200×900 or 1600×1200 | JPG/WebP | 300 KB |
| Gallery (multi-angle) | 800×800 | JPG/WebP | 200 KB |
| Selling point | 600×400 | JPG/WebP | 150 KB |
| Thumbnail (auto-generated) | 200×200 | WebP | 30 KB |

## Per-SKU Image Plan (Recommended for Demo)

For each SKU, prepare:
- 1 × hero image
- 3-4 × gallery angles
- 2-3 × selling point images
- 1 × thumbnail (or auto-generated by backend)

Total: ~5-8 images per SKU.

## Sources

For demo purposes, images can come from:

1. **Official product photography** (best): downloadable from brand websites
2. **Self-shot photos**: take 5-8 angles with a smartphone, edit lightly
3. **AI-generated** (fallback): Stable Diffusion / Midjourney for hard-to-find products

## Optimization

Before committing, all images should be:
- Compressed via [TinyPNG](https://tinypng.com/) or [Squoosh](https://squoosh.app/)
- Stripped of EXIF metadata
- Ideally in WebP format (or JPG for compatibility)

## Backend Image Serving

The backend exposes images at `/images/<filename>` and supports dynamic resizing:

```
/images/iphone-15-pro-hero.jpg              # Original
/images/iphone-15-pro-hero.jpg?w=200        # Width 200, auto height
/images/iphone-15-pro-hero.jpg?w=800&q=75   # Width 800, quality 75
```

WebP conversion happens automatically when client supports it (`Accept: image/webp`).

## Adding New Images

1. Place image in this directory following naming convention
2. Reference it in the corresponding product YAML at `knowledge/products/<sku>.yaml`
3. Restart backend (or it auto-reloads in dev mode)
